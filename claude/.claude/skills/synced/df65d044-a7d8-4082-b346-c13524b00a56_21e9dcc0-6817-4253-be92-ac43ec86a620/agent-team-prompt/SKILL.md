# Agent Team Prompt Generator

사용자가 원하는 작업을 설명하면, Claude Code에서 **실제 Agent Team** (subagent가 아닌)이 생성되는 최적의 프롬프트를 만든다.

## 워크플로우

### 1단계: 공식 문서 확인

프롬프트를 만들기 **전에** 반드시 최신 공식 문서를 확인한다:

```
WebFetch https://code.claude.com/docs/en/agent-teams.md
```

WebFetch가 실패하면 (robots.txt 등) 번들된 레퍼런스를 사용:

```
Read references/agent-teams-docs.md
```

이 문서에서 확인할 핵심 사항:
- 현재 지원되는 기능과 제한 사항
- 팀 생성 트리거 키워드
- 작업 의존성 문법
- 통신 방식 (message, broadcast)

### 2단계: 사용자 요구 분석

사용자의 요청에서 다음을 파악한다:

- **목표**: 최종적으로 무엇을 달성하려는가?
- **입력**: 어떤 파일, 코드베이스, 문서가 관련되는가?
- **병렬성**: 작업이 진짜로 병렬 실행의 이점이 있는가?
- **팀원 간 통신 필요성**: 팀원들이 서로 대화해야 하는가?
- **출력**: 최종 결과물은 무엇인가?

> **판단 기준**: 작업이 순차적이고 팀원 간 통신이 필요 없다면, Agent Team 대신 subagent를 권장하라. 토큰 비용이 훨씬 낮다. 사용자에게 이유를 설명하고 선택하게 한다.

### 3단계: 프롬프트 생성

아래 구조를 따라 프롬프트를 생성한다.

...

{의존 관계가 있으면 명시}

## 프롬프트 작성 규칙

### 필수 트리거 표현

Agent Team이 subagent가 아닌 실제 팀으로 생성되려면, 다음 표현을 **반드시** 포함해야 한다:

- `"에이전트 팀을 만들어"` 또는 `"Create an agent team"`
- `"팀원들을 spawn해"` 또는 `"Spawn N teammates"`
- `"tmux 분할 창"` (tmux pane을 원하는 경우)

절대 사용하면 안 되는 표현 (subagent로 해석됨):
- `"Agent Team을 만들어"` (대문자 혼용)
- `"teammate1, teammate2..."` (번호 매기기)
- `"순서대로 실행해"` (순차 실행 암시)

### 팀원 이름은 역할 기반

번호(teammate1, 2, 3) 대신 역할 이름을 사용한다:
- `extractor`, `verifier`, `reviewer`, `writer`, `architect`, `researcher`
- Claude Code가 메시지 라우팅을 더 잘 처리한다

### 팀 크기는 3-5명

- 대부분의 작업에 3-5명이 적절
- 팀원당 5-6개의 작업 유지
- 검증 역할은 최대 1-2명 (중복 검증은 토큰 낭비)

### 병렬 vs 순차 판단

| 패턴 | 권장 |
|---|---|
| 작업들이 독립적으로 실행 가능 | Agent Team (병렬) |
| A 완료 → B 시작 → C 시작의 체인 | Subagent (순차) |
| 팀원 간 토론/반박 필요 | Agent Team |
| 같은 파일을 여러 명이 편집 | 단일 세션 |

### 통신 명시

팀원 간 메시지 교환이 필요하면 명시적으로 지시한다:
- `"완료되면 {팀원명}에게 결과를 메시지로 보내라"`
- `"팀원들이 서로 직접 메시지를 주고받으며 작업을 조율하도록 해"`

### 파일 충돌 방지

두 팀원이 같은 파일을 편집하면 덮어쓰기가 발생한다. 각 팀원이 다른 파일/디렉토리를 소유하도록 설계한다.

### 충분한 컨텍스트 제공

팀원은 리더의 대화 기록을 상속하지 않는다. 생성 프롬프트에 작업에 필요한 모든 정보를 포함해야 한다:
- 관련 파일 경로
- 프로젝트 구조
- 사용할 기술/도구
- 기대하는 출력 형식

## 예시: 좋은 프롬프트 vs 나쁜 프롬프트

### 나쁜 프롬프트 (subagent로 해석됨)

```
Agent Team을 만들어.
* teammate1: PDF에서 내용 추출
* teammate2: teammate1 결과 검증
* teammate3: 문서 작성
```

문제점:
- `"Agent Team"` 대문자 혼용
- 번호 기반 팀원 이름
- 완전 순차적 (병렬 이점 없음)
- 팀원 간 통신 미지시

### 좋은 프롬프트 (실제 Agent Team 생성)

```
에이전트 팀을 만들어서 아래 작업을 수행해. tmux 분할 창으로 팀원들을 spawn해.

## 목표
PR #142를 다각도로 검토해서 종합 리뷰를 작성한다.

## 팀 구성 (3명의 팀원을 spawn)

### security-reviewer (보안 검토)
src/ 디렉토리의 변경 사항을 보안 관점에서 검토한다.
토큰 처리, 세션 관리, 입력 검증에 집중.
발견한 취약점을 severity rating과 함께 리더에게 보고.

### perf-reviewer (성능 검토)
변경된 코드의 성능 영향을 분석한다.
N+1 쿼리, 불필요한 메모리 할당, 알고리즘 복잡도에 집중.
발견 사항을 리더에게 보고.

### test-reviewer (테스트 커버리지 검토)
테스트 파일들을 검토하고 커버리지 갭을 식별한다.
edge case, error path, integration test 누락에 집중.
발견 사항을 리더에게 보고.

## 추가 지시
세 팀원 모두 완료되면, 리더가 종합 리뷰를 작성한다.
팀원들이 서로의 발견에 대해 의견이 있으면 직접 메시지를 보내라.
```

## 출력 형식

프롬프트를 생성한 후, 다음을 함께 제공한다:

1. **생성된 프롬프트** (코드 블록으로)
2. **왜 이 구조인지** (간략한 설명)
3. **사전 확인 사항** (tmux 설치 여부, settings.json 설정 등)
